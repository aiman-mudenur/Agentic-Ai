  unchanged: 4 tool(s) (compute_scope_validation, read_assignment_rubrics, read_notes_store, read_submission_records)
             query keys ('course_code',), result type NotesReadResult

  the course code's value differs, and that is configuration, not code:
  the two sources serve different corpora, so each is asked about a
  course it actually has. A deployment supplies that id alongside
  SOURCE_ADAPTER. What the agent contributes is the query shape: ('course_code',).

  changed  : course name and provenance, both of which come from the
             source and from nowhere else. That is what a swap is.

  so the refusal is scope-based, not a blanket deny

  what the governed path leaves behind:
    ledger rows for read_submission_records : 3
    names the caller                        : True
    names the missing scope                : True

  where a caller would put a credential to escalate:
    ConnectorClient.read(endpoint, payload)
    -> nothing. The token is held by the client, not the call.

  A bypass is not an error, which is why it survives review. The data
  is real and the code works. What is missing is the row above, and
  the row is what makes 'later' arguable.
